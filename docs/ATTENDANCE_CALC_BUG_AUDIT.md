## 高嚴重度

### B1 夜班跨午夜下班打卡歸屬錯誤

**位置**：`src/app/api/attendance/clock/route.ts:187-200`（記錄查找）、`:360-379`（孤兒記錄建立）

**現象**：下班打卡永遠以「打卡當下的台灣日期」找當日記錄（`getTaiwanTodayStart(now)`）。夜班跨午夜下班時，昨天那筆已打上班卡、未關閉的記錄**不在查找範圍內**。

**重現情境**（班表 22:00–06:00）：
1. 7/4 22:00 打上班卡 → 建立 workDate=7/4 的記錄。
2. 7/5 06:00 打下班卡 → 以 7/5 查找，找不到 7/4 的未關閉記錄 → 走 `:360` else 分支，**另建 workDate=7/5、只有下班卡、regularHours=0 的孤兒記錄**。
3. 結果：7/4 記錄永遠沒有下班時間（工時 0），7/5 是無效孤兒（工時 0）——**整晚白做**。
4. 連續夜班更糟：7/5 22:00 打上班卡時，孤兒記錄已存在且 clockInTime 為空 → 上班卡寫進孤兒 → 該記錄變成 clockIn 22:00、clockOut 06:00（**下班早於上班**），`calculateAttendanceHours` 算出 `max(0, 負數) = 0`。髒資料鏈每天延續。

**諷刺點**：`work-hours.ts:91` 明明完整支援跨日班計算（`endTime <= startTime` 自動 +24h），但打卡路由的日錨定讓下班時間根本到不了正確的記錄上。

**影響**：夜班員工的工時、加班、薪資、全勤全部歸零或錯亂。

**修法方向**：下班打卡查找時，若當日無未關閉記錄，回頭找「昨天有上班卡、無下班卡、且班別跨日」的記錄。

### B2 考勤扣薪的跨日盲區

**位置**：`src/lib/payroll-processing.ts:403-410`（`getClockMinutes`）、`:461-467`（比對邏輯）

**現象**：`getClockMinutes` 只回傳「當日時分」（hour×60+minute），無跨日位移。夜班比對全錯：

| 情境（班表 22:00–06:00） | 期望 | 實際 |
|--------------------------|------|------|
| 00:30 才打上班卡（遲到 2.5 小時） | 遲到 | `30 > 1320` 不成立 → **測不到** |
| 23:50 就打下班卡（早退 6 小時） | 早退 | `1430 < 360` 不成立 → **測不到** |
| 05:00 打下班卡（早退 1 小時） | 早退 | `300 < 360` 成立 → 碰巧對 |

**對照組**：`src/lib/perfect-attendance.ts:105-110` 的 `getTaiwanClockMinutes` **有**處理跨日（打卡日期 > 班表日期時 +24h）。同一次夜班遲到，全勤扣 0.5 天、薪資卻不扣——兩套模組對同一行為判定不同。

**影響**：夜班遲到/早退的薪資扣款漏算（目前受 B1 影響，夜班多半連打卡記錄都是壞的，此 bug 被掩蓋；修好 B1 後會浮現）。

**修法方向**：抽出 perfect-attendance 的跨日位移邏輯共用，或 payroll 端補同款 dayOffset。

### B3 請假撤銷/作廢不還原班表

**位置**：核准端 `src/app/api/leave-requests/[id]/route.ts:223-234`；撤銷端 `cancel/route.ts`、`void/route.ts`（**全無 schedule 相關程式碼**，已 grep 確認）

**現象**：核准請假時，把請假範圍**每一天**的班表改寫為 `shiftType: 'FDL', startTime: '', endTime: ''`——原班表時間被**覆蓋且未備份**。撤銷（cancel）或作廢（void）請假時，特休餘額會正確回補，但**班表不會還原**。

**重現情境**：
1. 員工請 7/10 特休，核准 → 7/10 班表從「09:00–18:00」變成 FDL 空時間。
2. 員工取消該假單 → 假回來了，**但 7/10 班表永遠是 FDL 空時間**。
3. 員工 7/10 正常上班打卡 → 無班表窗口 → 工時走無班表分支（基準不同）、遲到/早退不判定、考勤扣薪跳過（`payroll-processing.ts:441-447` 對空 startTime 直接 continue）、全勤不監控。

**影響**：每一次「核准後撤銷」都永久破壞一段班表資料；該員工該日從此脫離所有考勤監控。無法從現有資料復原（原時間沒存）。

**修法方向**：核准時不要覆蓋班表原欄位（另存請假時數欄位，如既有的 specialLeaveHours 模式），或撤銷時從 ShiftDefinition 還原；存量壞資料需比對班表模板修復（類似既有 repair CLI）。

### B4 曠職統計是死程式碼

**位置**：`src/lib/perfect-attendance.ts:312-315`

**現象**：曠職次數統計依賴 `record.status === 'ABSENT'`，但**全站沒有任何程式碼寫入 ABSENT**（已 grep 確認：唯一出現處就是這行讀取）。考勤記錄只在打卡時建立——沒來上班的人根本沒有記錄，更不會有 ABSENT 記錄。

**影響**：`absentCount` 恆為 0，**曠職完全不影響全勤獎金**。員工整月不來，只要沒有請假單，全勤照發（受影響請假 affectedLeavedays 也是 0）。

**修法方向**：改為「有班表、無打卡記錄、無核准請假」推導曠職（與 `payroll-processing.ts:457` 的缺勤判定邏輯對齊——那邊反而是對的）。

## 中嚴重度

### B5 全勤應出勤天數與排班脫鉤

**位置**：`src/lib/perfect-attendance.ts:296-304`

**現象**：分母 `workDays` = 該月**週一至週五**的天數，完全不看：
- 實際 `Schedule`（排班制員工週六上班、平日休都算錯）
- `Holiday` 表（國定假日仍算應出勤 → 假日多的月份全員出勤比例被稀釋，全勤獎金按比例縮水）

而分子的扣項（遲到/早退）卻是依**實際班表**判定（`countPerfectAttendanceScheduleIssues` 吃 Schedule）——分子分母基準不一致。

**重現情境**：2026 年 10 月有多天國定連假，週一至五共 22 天，實際應出勤 18 天。全勤員工 ratio = (22-0)/22 = 100% 沒事；但一次遲到的員工 = 21.5/22 vs 應為 17.5/18，比例失真；排班制員工誤差更大。

**修法方向**：分母改為「該月有效班表天數（扣 OFF/FDL）」，與分子同源。

### B6 請假跨月查詢漏抓 + 整段計入

**位置**：`src/lib/perfect-attendance.ts:274-293`（查詢）、`:319-324`（累計）

**兩個問題**：
1. **區間重疊條件錯**：`OR [startDate 在本月, endDate 在本月]` 漏掉「起訖都在月外、整段跨越本月」的長假（正確寫法：`startDate <= 月底 AND endDate >= 月初`）。
2. **不按月切割**：`affectedLeavedays += leave.totalDays`——6/28～7/3 的 6 天病假，在 7 月全勤計算中被扣**全部 6 天**（7 月實際只佔 3 天），6 月又再扣一次 6 天。跨月請假被雙重全額計入。

**修法方向**：修正重疊條件 + 只累計落在本月內的天數。

### B7 半天假處理錯誤

**位置**：`src/app/api/leave-requests/[id]/route.ts:227-233`（清空邏輯不分全天/半天）

**現象**：核准請假時，範圍內**每一天**的班表時間都被清空——半天假也不例外。上午請假、下午應上班的員工，當天班表已無 startTime/endTime：
- 下午的班完全不受遲到/早退監控（`isWorkingSchedule` 為 false）
- 考勤扣薪跳過該日（空時間 → continue）
- 工時計算走無班表分支，基準改變

反過來若不清空（假設改掉 B3/B7 的清空），現行 `countPerfectAttendanceScheduleIssues` 不知道請假存在——上午請假下午來上班會被判「遲到」扣 0.5 天全勤，`affectedLeavedays` 又扣一次請假——**雙重扣**。兩條路徑都不對。

**修法方向**：半天假保留班表時間、記錄請假時段；遲到/早退判定吃請假時段做豁免。

### B8 儲存工時 vs 重算工時分歧

**位置**：`src/lib/work-hours.ts:114-145`（`getStoredOrCalculatedAttendanceHours`）

**現象**：函式**重算優先**——只要以「目前的班表」重算出 totalHours > 0，就無視打卡當下存入的 `regularHours`/`overtimeHours`；儲存值只在重算為 0 時當 fallback。這與函式名暗示的「有存就用存的」相反。

**後果**：事後任何班表變動都會讓「records 顯示值」漂移：
- B3 的請假清空班表 → 該日重算基準從「班表窗口」變「純打卡時間扣 break」→ 顯示工時無聲改變
- 修 breakTime（系統有 `repair-schedule-break-time-cli.ts` 前科，代表發生過）→ 歷史顯示值全變
- 打卡時寫入值、records 顯示值、薪資實際採用值三者可能各不相同——對帳惡夢

**修法方向**：擇一並貫徹——「儲存值為準（有值就用）」或「永遠重算（那就別存）」；建議儲存值為準，班表修正後以明確的重算工具批次更新。

### B9 非公務時數計入加班顯示

**位置**：`src/lib/work-hours.ts:104-105`

**現象**：`overtimeHours = rawHours − standardHours`，而 rawHours 包含**班表窗口外**的時間（僅扣 break）。員工提早 1 小時到（即使打卡時選了「非公務」原因），這 1 小時照樣墊高 rawHours → 寫入記錄的 overtimeHours 含未核准時數。

**重現情境**：班表 09:00–18:00（休 1h、標準 8h），員工 08:00 到、18:00 走，原因選「非公務提早」→ 記錄寫入 overtimeHours = 1.0。

**緩解與殘留**：薪資端有 `resolveApprovedAttendanceOvertime`（`payroll-processing.ts:807-822`）以核准加班單校正實發時數——**錢大致不會多發**。但 records 頁、today-summary 顯示的是未過濾的 overtimeHours → 員工看到「我有 1 小時加班」卻沒錢，月月產生爭議客訴。

**修法方向**：顯示層改用與薪資同款的校正值，或記錄寫入時就只計班表內加班、班表外時數另欄存放。

### B15 特休核准與薪資給付疑似斷鏈（需業務確認）

**位置**：核准端 `leave-requests/[id]/route.ts:223-234`（只改 FDL）；薪資端 `payroll-processing.ts:774-777`（有薪假時數只認 `schedule.specialLeaveHours > 0`）

**現象**：經請假流程核准的特休，不會寫 `specialLeaveHours`（該欄位只由排班管理相關 API 寫入）。薪資的 `buildPaidLeaveAttendanceForPayroll` 只吃 specialLeaveHours/compLeaveHours——兩條路對不上。

**需確認**：若月薪制員工的底薪不依出勤時數（請假日照發），此斷鏈無實際影響；若任何計算依賴「特休日有時數」，經請假流程核准的特休會**漏給薪**，需人工在排班補時數。建議實測一位員工走完「請假流程核准特休 → 產生薪資」對帳確認。

## 低嚴重度

### B10 workHours=0 使全部時間變加班

**位置**：`src/app/api/attendance/clock/route.ts:334`、`today-summary/route.ts`（同款）

`todaySchedule?.workHours ?? undefined`——workHours 為 **0**（非 null）時不會落到預設 8，而是把 standardHours 設為 0 → `regularHours = min(x, 0) = 0`、全部時數變 overtimeHours。OFF 日若殘留 workHours=0 的班表且員工打卡，記錄異常。若「假日上班全算加班」是刻意設計，應以明確條件表達而非依賴 `??` 對 0 的行為。

### B11 班別時間 "24:00" 被靜默忽略

**位置**：`src/lib/work-hours.ts:26-31`

`parseTimeToMinutes` 拒絕 hour > 23——若有班別以 "24:00" 表示午夜結束，`scheduleEndMinute` 為 null → 整個班表窗口被靜默忽略，計算走無班表分支（break 直接從總時數扣、無窗口裁切），結果與有班表時不同且無任何警告。

### B12 四捨五入不閉合

**位置**：`src/lib/work-hours.ts:21-23,107-111`；`payroll-processing.ts:412-414,487`

regular/overtime/total 各自四捨五入到 0.01，`regular + overtime ≠ total` 可差 ±0.01；扣薪再疊 `Math.round(時數 × 時薪)`。單筆無感，月報表加總對帳時出現分位差。慣例做法：分鐘整數運算到最後一步才轉小時。

### B13 遲到/早退無寬限且兩套度量不一致（設計題）

全勤：遲到 1 分鐘扣 0.5 天獎金（`perfect-attendance.ts:328`，已知無寬限版）；扣薪：同一分鐘扣 1 分鐘工資（`payroll-processing.ts:485`）。同一行為雙軌懲罰且度量不同（次數 vs 分鐘），是否合意需 HR 定調；至少寬限分鐘數應兩邊共用同一設定。

### B14 `new Date(toLocaleString())` 脆弱時區模式

**位置**：`src/lib/timezone.ts:21-28`（`getTaiwanNow`/`toTaiwanDate`）、`clock/route.ts:213`、`leave-requests/[id]/route.ts:44-51`（`toYmd`）

依賴 `Date` 解析 locale 字串（實作相依、失去秒/毫秒），而同專案 `timezone.ts:31-67` 已有 `Intl.formatToParts` 的正確工具。功能上目前多用於顯示與日期字串，尚未證實造成錯值，但屬同一件事兩種寫法的地雷——應統一到 formatToParts 系列並刪除脆弱版本。

## 建議修復順序

1. **B3 + B7（請假-班表資料破壞）**——不是邊角案例，每次核准/撤銷請假都在破壞資料，且損害不可逆（原班表時間沒存）。先止血：核准時保留班表原時間。
2. **B4 + B5 + B6（全勤計算）**——直接影響每月獎金金額且恆常發生；三項都在 `perfect-attendance.ts`，可一次修：曠職改推導、分母改班表天數、請假按月切割。
3. **B1 + B2（夜班）**——先確認業務是否有跨午夜班別：有 → 高優先（現在夜班工時全錯）；無 → 加防護（建立跨日班別時警告）後降級。
4. **B8 + B9（顯示一致性）**——消除「員工看到的」與「薪資算的」分歧，減少客訴。
5. **B15 實測確認**後決定是否修；**B10–B14** 見縫插針。

**修復前建議**：先為 `work-hours.ts`、`perfect-attendance.ts`、`calculateAttendanceSalaryPenalty` 補齊夜班/半天假/跨月假的測試案例（現有測試未覆蓋這些情境，否則不會活到今天）——先讓 bug 有測試釘住，再動手修。
